## 三、发现的问题

### P1（缺陷）：HTTP 客户端不设 User-Agent，ocgo 三端点被 Cloudflare 指纹封禁

- **现象**：`plan vol` 插桩探针捕获 `降级链全部耗尽：ocgo HTTP 403 error code: 1010 ×2、ocgo-ali 403 1010、ali/glm 读超时`
- **根因**：`loom/edge/client/http.py` `_default_transport` 用 `urllib.request` 且未设 UA 头，默认 `Python-urllib/3.13`。实测（无密钥探测）：默认 UA → `403 error code: 1010`（CF 浏览器签名封禁）；浏览器 UA → 穿透 CF（404 为裸 GET 未命中路由，预期）
- **影响**：降级链 5 端点中 3 条永久不可用；只剩 ali/glm 硬扛
- **建议**：`_default_transport` 补一行常规 UA 头（一行修复），并补 cassette 用例断言请求头

### P2（健壮性）：ali/glm 端点 300s 读超时频发

- `timeout=300` 写死；大体积 JSON（40 章卷纲）生成在 ali/glm 上经常 >300s → 读超时
- 建议：timeout 可配（环境变量）+ 端点级重试（当前网络错误直接放弃该端点）

### P3（可观测性）：plan 三次失败的具体原因对用户不可见

- `plan_vol` 三次尝试的 gate 违例/ schema 校验错误只回喂 LLM，最终 `PlanRejected` 未填充 `issues`，工作区无草稿残留、run-ledger 无事件（A8 仅覆盖 settle 链路）
- 报错文案"需人工改纲"，但人工看不到任何一次生成的原稿与违例清单，无从下手
- 建议：失败尝试落 `工作区/`（gitignored）+ `PlanRejected` 携带最后一次 issues

### P4（lint）：ruff 8 项违规

- 见总表；均为机械修复（`l`→`line`、import 上移）

## 四、已验证的正确行为（非缺陷确认）

1. **空总纲 fail-closed 正确**：plan_vol 对空白骨架书仓三次拒绝、零残留、零误提交；init 提示"先完成总纲再进规划环"与实际行为一致
2. **中断安全**：运行中 kill 掉 plan 进程后，doctor 报告健康、无 stale 锁（写锁 pid 探活生效）
3. **域异常可读化**（第二轮审阅 P2-4）生效：PlanRejected/ProviderError 均以 `[loom]` 前缀 + 退出码 1 输出，不裸抛 traceback

## 五、未闭环项

- `plan vol → plan batch → next → settle → scribe` 全链路真实 LLM 闭环：被 P1/P2 阻塞，修复 UA 后需重测
- `batch arm/run`、`review`、`golden`、`volsummary`、`migrate`、`bench` 未冒烟（依赖前序闭环或真实书稿）
