## 四、本轮新发现（A1–A13）

### 4.1 建议随 P0 spec 冻结一并解决（严重度：中）

**A1 豁免机制没有 schema 载体。** 三处机制依赖"豁免"：每章结算必须 touch ≥1 条条目（豁免走决策卡，§2.2）、plan_gates 第 5 道"否则显式豁免卡"（§4.1）、章纲机检"每章 touch ≥1"（§4.1）。但决策卡四段（盘面/提案/合同/备选）与章纲卡字段（touch 条目/场景数/钩子类型/时间锚点/字数档）均无豁免字段，"豁免卡"是决策卡的一种取值还是新卡型也未定义。不补载体，机检无法区分"违例"与"豁免"，豁免门（§2.2 明言的逃生口）落不了地。

**A2 写侧数据 schema 家族未进 P0 冻结清单。** M2 补的是规划侧四张；而机检与 prep 直接消费的写侧结构——正文 front matter（章目/时间锚点/条目变动声明/合同摘要）、设定条目家族（名册关键词触发器、信息差、时间线"章/书内时间/事件/在场人物"）、文体指纹.json 七维、题材 profile 字段——目前停留在 §3 的散文级描述。P0 的 repo 读写与 settle 没有这批 schema 无法动工。建议与四张 schema 同批冻结，或显式声明"以 §3 字段级描述为准"并逐字段成文。

**A3 gate 6"题材配比红线"口径未定义。** 卷纲 front matter 有"章节类型标注"，但该字段的枚举值未写死，与"主线/感情/支线"的映射未说明；且条目账本的类型轴（伏笔/悬念/感情线）与配比轴（主线/感情/支线）是两套分类，不能直接互推。P0 冻结卷纲 schema 时需写死枚举与配比计算口径。

### 4.2 排期与一致性微调（严重度：低–中）

**A4 plan_deviation / retcon 两类 signals 未排期。** signals 共七类，P1a 埋 4 类、P3 补 batch_breaker，但 plan_deviation（依赖 P1b 产出的章纲计划，应随 P1b 埋点）与 retcon（retcon 事务 P0 即存在）两类在任何 Phase 行均未提及——这是 M3"采集不得晚于动作"原则的残留尾巴。P4 首轮优化要分析 plan_deviation（规划 prompt 是第二优化对象），不埋就没数据。建议 P1b 行补 plan_deviation、P2 或 P3 行补 retcon。

**A5 盲测集时序矛盾。** R10 缓解措施写"P1a 起盲测集做 prompt 回归"，但盲测金标准集 v1 建设排在 P1b（§6），§5.3 也说 P1b 内才出实测数据。二选一：P1a 先建最小子集（如 6 段）供 prompt 回归、P1b 扩到 24 段全量；或把 R10 的时点改为 P1b。

**A6 Book Map 初版时点矛盾 + P1a 验收的规划输入来源未说明。** §6 P1a 行含"卷纲骨架版 Book Map"，§4.2 却说 Book Map 初版"P1b 起"；且 P1a 阶段尚无 plan vol / plan batch（在 P1b），5 章验收所需的卷纲、章纲卡、决策卡从何而来（作者手写？）全文未交代。建议明确"P1a 用手写卷纲/章纲测骨架版 Book Map 与单章环"，并统一 §4.2 的时点表述。

**A7 P0 范围增而估时未变。** 较 v2.0 的 P0，v3.0 的 P0 新增：写入所有权矩阵 + 书仓写锁（M6/N5）、测试骨架（N4）、四张 schema 中新列入的卷纲与决策卡两张，估时仍为 7–9 人日。降本依赖"矩阵/锁自 v6 run-ledger 移植适配"这一未言明的前置假设——若 v6 移植件不含锁逻辑，P0 有超估风险。另外 N4 的 edge cassette 录制回放未点名到任何 Phase 行。建议 P0 行补前置假设注记，cassette 归入 P1a。

### 4.3 落盘与命令面（严重度：低）

**A8 run-ledger 的落盘位置未定义。** §3 书仓树中，演化/ 只列 signals.jsonl；run-ledger（append-only 审计链，"任何一章可完整回放生产过程"的根基，§4.6/§5.4 反复引用）放哪、是否入 git 未写。工作区/ 是 gitignored，不宜承载审计链。建议显式列入树（如 演化/run-ledger.jsonl）。

**A9 scribe 产物的落库事务归属未闭合。** settle 定义为"一次 git commit"，而章摘要 / 事实提取入账 / 金句候选都产生于结算之后（§4.2 第 6 步"结算后 scribe…"）——这些产物需要第二次落库动作，其事务边界、commit 协议标注（机器协议五种之外如何署名）与写入所有权矩阵中的授权未说明。另"按 10 类事件枚举做事实提取"的 10 类清单全文未给出，建议列入 §8 开放议题或在 P1a 细化时成文。

**A10 cli.py 命令清单不全。** §4.6 的 `loom ledger`、§5.2 的 `loom memory correct` 未出现在 §5.1 的命令列表（init/plan/next/prep/render/check/review/settle/batch/evolve/doctor/migrate）中。

### 4.4 备忘（信息级）

**A11 "定稿/"目录语义张力。** 该目录混装 append-only 内容（正文、摘要、卷摘要）与可变内容（设定条目状态迁移 active→outdated、文体指纹滚动值更新）；"定稿只增不改"的适用粒度（正文级还是目录级）需在 spec 写清，避免实现时把设定更新误判为违约。

**A12 题材库资产未排期。** 13 题材 + 37 模板 + 9 张知识表（§4.4）的建设/迁移未列入任何 Phase。若资产在 v6 已有，建议在 P1a 行点名"随 CSV 检索移植顺带迁入"；若无，则是一块漏估的工作量。

**A13 上游指针过时未处理。** §9 自述"docs/新建目录/README.md 的最终方案指针仍指向 v1.1，待人工更新"——本轮仍未处理。该文件位于另一工作区（opc_space），本报告不代改，提醒 Human 择机更新。

## 六、总体评价

v3.0 作为三稿迭代的终审版，质量扎实：两轮审阅的修正真实落地而非纸面合并，估时与成本表经得起重算，治理设计（盲测集三重角色、拒绝式约束、fail-closed、写入所有权）在同类方案中属于少见的严谨。本轮发现的 13 项集中在 **spec 冻结边界**（A1–A3：机检所需字段在四张规划侧 schema 之外仍有无载体者）与**排期收尾**（A4–A6：前移与拆分 P1 后的残留不同步），无一是架构级返工。按第五节清单处理后，即可按 §6 开工 P0。
