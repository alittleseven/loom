> 版本 v3.0（2026-08-28）。在 v1.1（GLM 5.3 Flash 整理）与 v2.0（Kimi3 审阅修订版）基础上终审整合，取代 v2.0 成为**动工前基线**；v1.1 / v2.0 同目录存档，冲突处以本文为准。本文**自足**：每个机制就地描述，不依赖外部文档。仍非终稿的部分见 §8 开放议题；演进接口（spec_version / seam_version / 开放清单）全程保留。

## 1. 产品定义与设计原则

### 1.1 产品定义

> **一个让"会遗忘、会幻觉、没有品味的天才写手"（大语言模型）连续工作 300 章不出事的生产系统。**

它不是"prompt → 章节"的生成器。中文网文长篇（60–120 万字）对 AI 写作有三个硬问题，按难度排序：

1. **一致性**：百万字尺度上设定不崩--角色名、力量等级、时间线、伏笔不漂移不矛盾；
2. **上下文经济学**：任何模型的上下文窗口都装不下一本书，必须精确控制"模型每章看见什么"，且成本不随书变厚而膨胀；
3. **品味对齐**：写得像作者不像 AI--去 AI 味、守题材套路、踩爽点节奏。

生成能力排第四：今天的模型文笔已够用，瓶颈全在系统。

### 1.2 十条设计原则（全方案最高准则）

1. **一致性是契约，不是记忆**--能被脚本核验的断言（写进结构化文件）优先于"让模型记住"。
2. **模型写增量，人和 git 存正典**--LLM 永远只产草稿，经过校验、以原子事务落入 git 的才叫事实。
3. **能数的不让模型估**--一切可脚本计算的检查（字数、重复率、时间线、人名、条目兑付）零 LLM 成本、确定性执行。
4. **智能在边缘，状态机在核心**--内核不含任何 LLM 调用，保证确定性；所有模型调用集中在可替换的边缘层。
5. **上下文是编译出来的，不是塞进去的**--每章给模型看的内容由编译器按恒定预算装配，与全书长度无关。
6. **作者的交互单位是决策，不是聊天**--作者看的是结构化"决策卡"，做的动作只有采纳/改卡/选备选；注意力是唯一不可再生资源。
7. **品味从行为学，不从问卷问**--作者每次否决、改稿、打回都被旁路记录，零额外交互地沉淀为风格资产。
8. **成本像电表，透明且亚线性**--逐章记账，模型分档路由，总成本随章数线性而非随书膨胀。
9. **进化有红线**--自我优化只发生在离线环节，机检逻辑、结算事务、条目结转等核心永不自我修改。
10. **格式即产品**--书仓格式带版本号（`spec_version: loom-1`），工具只是该格式的一个参考实现；书比工具活得久。

## 2. 总体架构

### 2.1 三层 + 两条缝 + 一条闭环

```
┌─ 品味闭环 evolve/（离线，永不进运行时）──────────────────────┐
│ signals 旁路采集 -> 分析提案 -> bench 回归 -> holdout 对照        │
│   -> 作者批准合并 -> 快照可回滚                                  │
│ 资产：金句库 · 风格宪法 · 场景技能（都长在书仓里，随书走）        │
└──────────────────────────────────────────────────────────┘
┌─ 智能边缘 edge/（全部 LLM 调用，可插拔）─────────────────────┐
│ 渲染器 · 事实审/编辑审（双镜头）· scribe（摘要+事实提取）·       │
│ 金句收割分类 · 规划生成（卷纲/批次章纲）                        │
└─────缝① 工作区文件协议（带 seam_version；宿主 agent 亦可驱动）──┘
┌─ 确定性内核 core/（零 LLM）────────────────────────────────┐
│ repo 书仓读写 · prep 上下文编译 · checks 机检十项+plan_gates六道 │
│ settle 原子事务 · staging 批次连写+熔断 · ledger 记账 · migrate │
│ doctor 体检                                                   │
└──────────────────────────────────────────────────────────┘
        loom-1 书仓：一个 git 仓库 = 一本书，文件即真相
```

| 层 | 职责 | 关键约束 |
|---|---|---|
| core | 书仓读写、上下文编译、全部检查、结算事务、批次状态机、记账、体检、迁移 | 零 LLM、确定性；环境操作经 `RepoPort` 接口隔离，可注入测试替身 |
| edge | 所有模型调用 | 只经工作区文件与 core 交换数据（缝①）；模型侧经 `LLMProvider` 接口隔离，路由可换 |
| evolve | 品味进化的离线循环 | 运行时永不读取 signals 调整行为；优化产物必须过 bench 回归 + 作者批准 |

**两条缝**：① core↔edge 之间只通过 `工作区/` 目录里的文件交换数据（文件带 `seam_version` 版本声明，core 容错读取 + 版本嗅探，不匹配时显式降级而非静默错读）--这条缝让任何外部 agent 也能驱动内核，生态位保留；② `core/legacy/` 目录物理隔离从旧工具移植来的 GPL 代码，为未来更换许可保留清洁重写的边界。

### 2.2 关键架构洞察（机制就地说明）

- **文件即真相，派生物可丢弃**：正文、设定、大纲、条目账本全是普通 Markdown/JSON 文件，git 历史就是版本史。唯一的持久派生物是 `.cache/index.db` 检索索引--删掉后可从源文件全量重建，重建结果一致是硬验收。
- **单一事实源**：旧工具曾把状态同时写进 state.json / index.db / summaries / 向量库多处，静默漂移后互相矛盾（"角色在 DB 里死了、在 state.json 里活着"）。本方案任何事实只在一处存正本，其余一律派生或丢弃。
- **一致性用条目账本管理**：伏笔、悬念、感情线三本账（统称"承诺"），每条一个文件（类型/强度/状态/开启章/期限章/最后推进章）。每章结算必须 touch 至少一条条目（豁免走决策卡）--这是对上游"声明制"的有意加强：连载追读需要硬纪律，豁免门保留逃生口；高强度条目超期未推进即产生"节奏债"，进熔断指标。
- **上下文编译而非堆砌**：Book Map（全书骨架摘要放头部）+ 历史压缩（L0/L1/L2 分层摘要）+ 触发式注入（设定条目带关键词触发器，本章出场才注入）三者合成 prep 编译器，把"每章 ≤5k token 恒定包"编译出来。
- **去 AI 味是管线不是终检**：风格约束（宪法禁词、同场景金句示例、题材节奏）作为固定槽位进每次渲染的输入，而不是写完再修。

## 3. 书仓格式 loom-1（数据模型）

一本书 = 一个 git 仓库，目录如下：

```
book.yaml                 spec_version: "loom-1"；预算/自治档/阈值/题材，平铺 ≤15 行
定稿/
  正文/ch0001.md          front matter（章目/时间锚点/条目变动声明/合同摘要）+ 正文
                          只增不改；改已定稿内容走显式 retcon(N) 事务
  摘要/ch0001.md          本章摘要 ≤150 字 + 承接点（L2 层，settle 后自动生成）
  卷摘要/vol01.md         卷摘要（L1 层，卷末由章摘要合成）
  设定/{名册,世界观,信息差,时间线,角色}/
                          每条一文件，平铺 front matter，带稳定 id；
                          外部引用只走 id 不走路径（为未来系列书共享设定留句法）；
                          时间线条目含 章/书内时间/一句话事件/在场人物（append-only）
  记忆/文体指纹.json      七维文风基线 + 滚动值
大纲/
  总纲.md
  卷纲/volNN.md           每卷一文件，散文段（卷目标/主线推进/卷末钩子）
                          + 结构化 front matter（高潮点章号列表/条目计划=条目id×
                          开启|推进|兑付×期限章/时间跨度锚点对/章节类型标注）
                          --plan_gates 六道的全部数据源
  章纲/chNNNN.md          章纲卡（每章一文件，见 §4.1）
  条目/{伏笔,悬念,感情线}/ 三本账，每条一文件（类型/强度/状态/开启章/期限/最后推进）
文风/
  风格宪法.md             禁词/禁句式/口癖 + 否决入宪规则（每条带出处章号）
  金句库/<场景>.md        每场景 ≤20 条（LRU），结算时自动收割候选
  场景技能/<场景>.md      该场景的写法要点 + 正反例
  题材/<genre>.md         题材 profile：调性/节奏默认/毒点权重/配比红线/爽点间距预算
工作区/                   【gitignored】决策卡/本章材料/草稿/审稿/增强信号缓存
演化/                     signals.jsonl、bench 报告、进化提案、优化快照
bench/blindset-v1/        盲测金标准集（样本+评鉴口径+历次结果）
.cache/index.db           唯一持久派生物，SCHEMA_VERSION 变更即全量重建，可删
```

**格式纪律**：

- `spec_version` 首日落库；定稿只增不改；`retcon(N)` 是显式事务（分析受影响条目/设定并留痕）。
- commit message 使用机器协议 `ch(NNN)/vol(NN)/retcon(N)/fix(手改)/batch(N..M)`，正文行附条目结转声明（如 `条目: +F-058 ~S-031 $R-019`，+ 开启、~ 推进、$ 兑付；F=伏笔/S=悬念/R=感情线）。
- 读取端容错--未知字段保留写回，不丢单。
- **可机检的必结构化**（M2）：plan_gates 六道与章纲机检所依赖的字段（期限章/高潮点章号/时间锚点/条目计划/章节类型）一律为 front matter 结构化声明，散文段落仅作人读注解。四张 schema（卷纲/章纲卡/条目账本/决策卡）随 P0 spec 冻结。
- **配置-实现一致性**：book.yaml 每个字段必须有代码消费点，CI 检查无消费者字段直接报错（防纸面功能）。

**book.yaml 关键字段**：题材、自治档（L0/L1/L2）、批次大小（默认 8）、pack 预算（默认 ≤5k token）、节奏预算覆盖值（条目密度区间/爽点间距 N/期限余量 K）、模型路由表、熔断阈值（默认值在题材 profile，书级只放覆盖）。

**与上游格式的关系**：布局思想参考同领域开源项目 v7 规格的已验证设计，按 loom-1 独立实现，**不追踪其逐字节兼容**；保留未来"单向导出 v7 格式"桥接的可能（一句话预留，不承诺）。

## 4. 功能设计（按工作流）

### 4.1 初始化与规划环（`loom init` / `loom plan vol` / `loom plan batch`）

**init**：建书仓、写 book.yaml、装题材 profile，作者在 LLM 辅助下完成总纲与核心设定。

**规划环与写侧同构**--LLM 生成走 edge（中档模型），机检走 core（零 LLM），作者批准走决策卡：

- `loom plan vol`（卷纲）：输入 = 总纲 + 目标卷号 + 条目账本快照（active/overdue 清单与密度分布）+ 节奏预算表 + 上一卷卷末状态（在场人物/信息差/未兑付条目）。产出卷纲文件（散文 + 结构化 front matter，见 §3）。生成后过 **plan_gates 六道机检**：

| # | 检查 | 规则 |
|---|---|---|
| 1 | 条目期限合法性 | 每个新开条目的期限章 ≤ 卷末章 + K（默认 5） |
| 2 | 条目密度预算 | 本卷计划开启条目数 ∈ [min, max]（题材 profile） |
| 3 | 爽点间距 | 高强度条目/高潮点间隔 ≤ N 章 |
| 4 | 时间锚点单调 | 卷纲时间跨度与时间线账本不回退（程序化校验） |
| 5 | 超期兑付覆盖 | overdue 条目必须在本卷有兑付安排，否则显式豁免卡 |
| 6 | 题材配比红线 | 主线/感情/支线配比不越 profile 红线 |

  六道全部读取卷纲/章纲卡的结构化字段执行（M2）。违规 → 附错误反馈重生成 ≤2 次 → 耗尽则人工改纲。**阈值上线前用既有真实书稿（fantasy01）的大纲回测标定**，防误杀。

- `loom plan batch`（批次大纲）：生成 8 张**章纲卡**（每章一文件：本章 touch 的条目 ≥1、场景数 2–3、章末钩子类型、时间锚点、预计字数档）→ 章纲机检（每章 touch ≥1、钩子非空、时间锚点单调、跨批条目连续性--上批未兑付条目本批须有推进安排）→ 批次连读视图。
- **作者批准的对象是"条目结转计划"，不是文本**：连读视图呈现 8 章"开启→推进→兑付"的链路，动作三选：全收 / 改卡 / 改卷纲。
- **章纲卡 ↔ 决策卡**：章纲卡是**计划**（一批 8 张，plan batch 产出）；决策卡是**执行确认**（每章一张，L2 档由章纲卡模板化投影自动生成，L0/L1 档 LLM 参与提案后人工再改）。不重复、不丢段。

### 4.2 单章写作环（`loom next` / `prep` / `render` / `check` / `review` / `settle`）

每章流水线：**决策卡 → 上下文编译 → 渲染 → 机检 → 双审 → 结算**。

1. **决策卡（brief）**：作者唯一交互界面，四段固定--盘面（当前条目账本/时间线/近期剧情）、提案（本章计划：touch 哪些条目、场景安排）、合同（本章要兑现的可机检断言）、备选。作者动作只有采纳/改卡/选备选。连写模式（L2 档）下由系统按章纲卡模板化投影生成（零 LLM），人验推迟到批次末；L0/L1 档 LLM 参与提案与备选生成（成本表中决策卡一行的 LLM 开销仅 L0/L1 档发生）。
2. **上下文编译（prep）**：装配恒定预算的 **pack（≤5k token）**，槽位固定：
   - 合同段（本章断言）+ 风格段（宪法摘要 ≤400 字 + 同场景金句 1–3 条）；
   - 事实切片（本章出场实体--名册条目带关键词触发器，出场才注入，成本从 O(全书设定) 降为 O(本章出场)）+ 信息差过滤（读者此刻不该知道的内容不进包）；
   - 近期段（近 3 章摘要 + 主角状态快照）+ 反复读清单（活跃条目 Top 条目）；
   - 头部 Book Map：**初版**（P1b 起）= 当前卷纲骨架 + 活跃条目 Top5 + 主要在场人物一行卡；**完整版**（P5）= L0 全书骨架驱动的 30–50 行，让模型始终知道"自己在全书什么位置"；
   - **分层摘要保证第 300 章不劣化**：L2 章摘要（每章 settle 后生成）→ L1 卷摘要（卷末合成）→ L0 全书骨架（重编译触发统一为：每 6 批或每 50 章，先到者）。中距离剧情（50–200 章前）靠 L1/L0 召回，不靠向量检索撞运气；
   - 合同段与风格段在批次内基本不变，前置以命中 prompt 缓存（命中部分约 1/10 价格）。
3. **渲染（render）**：模型路由分档--常规章便宜档、关键章（卷末/大高潮/新设定章）强档，关键章另加**陪审团**：3–5 个不同模型各出一稿，按地板规则（如爽感强度标尺、无决策钩检测）淘汰，不过则重写。渲染是单章成本大头（约 78%），走裸 API 而非宿主 agent（后者开销 1.5–3 倍）。
4. **机检（check，零 LLM 十项）**：禁词/违禁句式、泄密扫描（信息差违例，依据时间线在场列）、专名一致性、履约 diff（章纲 planned vs 实际 covered/missed/extra）、时间线校验（程序化单调性/区间校验）、字数预算、n-gram 复读率、条目形式合法、题材配比、无钩检测（章末无钩子即拦；另设"连续 8 章无决策钩"趋势检查）。失败 → 附错误反馈重渲染 ≤2 次（第二次降温度+换 pack 版本）→ 耗尽进 CHAPTER_HALT。
5. **双审（review，中档模型）**：**事实审 + 编辑审**两个独立镜头，各自独立上下文，只找问题、不评分、不评文笔（防口味自我强化）。**输入构成定型**（M7）：事实审 = 草稿全文 + 合同段 + 活跃条目切片；编辑审 = 草稿全文 + 风格段 + 前章承接段（各 ≈5.5k）--与"机检先行"分工自洽：设定违例/泄密/专名一致性已由机检把守，双审只管脚本算不了的逻辑矛盾、叙事断裂与钩子失效。审稿结果以 sha256 令牌绑定到被审草稿，防张冠李戴。阻断级 issue → 重渲染 ≤1 次 → 耗尽 HALT。
6. **结算（settle，原子事务）**：校验 → 写文件树 → 一次 git commit → 缓存自刷 → 清工作区。三道保险：**断电/kill 回滚后仓库不脏**（故障注入硬验收）；**哈希防串稿**--被审草稿 sha256 与送审草稿一致才准结算（防"旧审配新稿"）；**批内工件失效锁**--作品契约中途变更时批内已产工件自动作废重产。commit 带机器协议 message 与条目结转声明。结算后 scribe 自动生成章摘要、按 10 类事件枚举做事实提取入账、金句收割（改稿 diff>30% 的段为候选 → tentative → 作者确认 → active → 进 pack 风格段）。

**重试预算 fail-closed**：任何环节重试耗尽即停，绝不带病过关。

### 4.3 连写批次与熔断（`loom batch`）

**批次**默认 8 章（可配 4–16），前置条件 = 卷纲存在 + 批次大纲（8 张章纲卡）经作者一次性批准。

```
BATCH_ARMED ──启动──▶ BATCH_RUNNING ──8章全部settle──▶ BATCH_REVIEW ──作者全收──▶ BATCH_ACCEPTED
                          │                              │
                          ├─ 章级重试耗尽 ─▶ 批次暂停       ├─ 单章打回 ─▶ retcon重做链 ─▶ RUNNING
                          ├─ 熔断触发 ─▶ BATCH_HALTED      └─ 改卷纲 ─▶ 重排批次大纲 ─▶ ARMED
                          └─ 批次末体检不过线 ─▶ BATCH_HALTED
```

不变量：批次内任何一章 settle 失败不影响已 settle 的章（每章独立原子 commit）；批次可暂停、可从任意章恢复（run-ledger 事件链断点续跑）。

**七项熔断（趋势层，全部零 LLM 可算，滚动窗口 10 章）**：

| 组 | 指标 | 熔断阈值（初始值，实测分布后标定） |
|---|---|---|
| 一致性 | 机检拦截率 | >30% |
| 一致性 | 履约 missed>0 的章占比 | >20% |
| 一致性 | 设定违例/泄密命中 | 任何 1 次即拦 |
| 文风 | 文体指纹 vs 基线漂移 | >2σ |
| 重复 | n-gram 重复率 / 桥段撞车 | 超基线 2 倍 |
| 节奏 | 节奏债（高强度条目超期数） | 超配置上限（默认 10 章） |
| 流程 | 重渲染率 | >25% |

标定注意：机检拦截率与重渲染率高度相关（同一次退化会被双重计数），实测分布后合并观察、熔断动作合并处理，避免同一问题连环放大。

触发 → 完成当前章 settle → 停批 → 诊断卡（触发指标/近 N 章趋势/建议动作）→ 作者选择：重编译 pack / 换渲染模型 / 降自治档 / 人工接管该章。熔断记录进 signals。熔断不取代单章闸门--单章问题当场拦，慢性退化按窗口拦。

**三档自治**：L0 全手动（每章人验）/ L1 半自动（关键环节人验）/ L2 批次自动（批次末人验）。**批次人验简报** = 8 章摘要链 + 条目结转清单 + 体检指标 + 成本账单，动作只有全收 / 单章打回（retcon 到该章重做）/ 改卷纲--把作者时间从"每章 30 分钟"压到"每批 30 分钟"。批次内滚动压缩：每章 settle 后更新 working memory（近 3 章摘要 + 本章章纲 + 主角快照）；批次结束更新 L1 卷摘要。

**失败处理矩阵**：机检失败→同章重渲染≤2；评审阻断→重渲染≤1；settle 失败→工作区原样保留、重放 run-ledger 恢复、不重渲染；打回第 k 章→retcon 分析 k+1..8 受影响条目/设定/摘要→标记待重排→从 k 重跑。

### 4.4 文风引擎（多中文风格的工程解）

三层结构，换风格 = 换 profile 目录，不改代码：

| 层 | 内容 | 来源 |
|---|---|---|
| 题材层 | 题材调性/节奏默认/毒点权重/配比红线/爽点间距预算 | 题材 profile 文件库（开局提供 13 题材 + 37 模板 + 9 张中文网文知识表：人设与关系/写作技法/命名规则/场景写法/桥段套路/爽点与节奏/金手指与设定等，BM25+CJK bigram 检索） |
| 作者层 | 风格宪法：禁词/禁句式/口癖 + 入宪规则（三次同类否决→系统提议→作者确认入宪，每条带出处） | 行为信号沉淀 |
| 样本层 | 金句库（改稿 diff>30% 自动收割，每场景 ≤20 条）+ 场景技能（写法要点+正反例，few-shot 注入渲染） | 结算管道（**随 P1a 落地**，M4--早期人工改稿密度最高，是金句素材最富集的窗口，风格资产从第一章开始复利） |

**文体指纹**（七维，全部脚本可算、零 LLM）：平均句长、句长方差、对话占比、平均段长、词汇丰富度（type-token ratio）、感官描写密度、比喻密度。作者认可的前 30 章定基线；每章 settle 更新滚动值，每 50 章体检比对，漂移 >2σ 告警。风格段每次渲染必带--**去 AI 味是管线而非终检**。

新风格冷启动：从题材层默认开始，靠金句收割与否决入宪快速"作者化"，前 10–20 章建议低自治档。

### 4.5 品味进化闭环（`loom evolve`，离线）

**signals 采集**（旁路记录既有动作，零额外交互；运行时永不读取）：

| type | 内容 | 进化用途 |
|---|---|---|
| card_action | 采纳/改卡/选备选 + 改动字段 | 决策卡/pack 提案质量 |
| settle_diff | 草稿 vs 终稿 diff 统计 | 渲染 prompt、场景技能 |
| gate_block | 机检 issue 五元组 + 作者是否标误报 | 阈值标定（不改逻辑） |
| review_disposition | 每条评审 issue 的采纳/驳回 | 评审 prompt 优化（第一优化对象） |
| plan_deviation | 章纲计划 vs 实际履约（大纲预测误差） | 规划 prompt 优化（第二优化对象） |
| batch_breaker | 熔断触发指标与处置 | 路由/编译权重策略 |
| retcon | 原因分类 | 规划层（卷纲/条目密度）改进 |

**采集时序（M3）**：signals 是既有动作的旁路记录，而动作从 P1a 就开始发生。采集随各环节落地**同步埋点**（决策卡/settle diff/机检拦截/评审处置/熔断各环节实现时各附一行 append 逻辑，边际成本≈0，append 由内核独占）；P4 只建离线分析与优化循环。若采集晚于动作，P4 首轮优化将无数据可析，丢失的窗口不可回补。

**优化循环**：分析提案 → 网文-bench 回归（指标：伏笔回收率/设定违例率/机检误报率/风格漂移）→ holdout 章节对照（≥5 章）→ 作者批准合并 → 快照可回滚。低频执行（每 30–50 章一轮），每轮只动一类旋钮。

**bench 的角色边界（M5）**：bench（含盲测集风格子集）对优化器是**拒绝式约束**--提案致指标退化即拒绝，但不向优化器提供任何可最大化的标量分数；**合并决策只依据作者对 holdout ≥5 章的盲判**。三重角色分工见 §4.6 盲测集条目。防的就是：优化器若能对冻结样本反复爬山，"永不作 fitness"会被软突破。

**红线（永不进化的东西）**：机检逻辑、settle 事务、条目结转、spec 兼容层。**机检通过率永不作为 fitness**--否则系统学会放水讨好闸门。

### 4.6 支撑功能

- **`loom doctor` 体检**：书仓完整性 + 每 50 章三项深度指标（文体指纹漂移 / 条目坏账 / 时间线孤儿）+ 断点续跑诊断与修复卡。
- **`loom migrate` 迁移器**：从旧工具（v6 格式书稿）迁入 loom-1--源只读、失败零残留、产出待校对清单；大纲/条目到章纲卡与条目账本的映射单列验收；迁移产物过一遍 doctor，零孤儿零坏账。
- **`loom ledger` 成本电表**：run-ledger 为 append-only 事件链，含 token/金额字段，逐章入账；批次报告与体检附账单，单章成本超预算自动亮黄灯（成本异常也是质量波动的旁证）。
- **盲测金标准集 `bench/blindset-v1`**：从作者亲笔章节抽 24 段（6 场景类型 × 强弱情绪 2 × 每格 2 段，300–500 字/段）冻结；候选模型跑同一集合、匿名盲排，产出"模型 × 场景类型"胜任矩阵 → 生成路由表。**三重角色写死**：① 路由事实源（唯一主动用途，作者盲排直接产出路由表）；② 网文-bench 的风格子集，仅作拒绝式约束（提案致其退化即拒绝，不提供优化标量）；③ 永不作 fitness。每 50 章轮换 20% 样本防陈旧。
- **RAG 可选插件**：向量检索只作"以前某段怎么写的"式回顾（embed→BM25→RRF 降级链，无 API Key 自动跳过、零网络守卫），**永不作事实召回主路径**--事实一律走结构化查询（设定条目/条目账本/时间线）。
- **已知限制（显式登记）**：品味闭环只对齐作者口味；发布后的真实读者数据（读完率/追读/评论）不进系统。远期若做发布通道，配套手动录入命令（平台后台读数 → signals 新事件 `reader_feedback`），零爬虫零风险。

## 5. 基本实现思路

### 5.1 技术栈与代码结构

- **Python 3.13 单体 CLI**，单一入口 `loom`；依赖最小化：`pydantic`（结构化输出与校验）、`GitPython`（git 操作）、标准库优先。单机运行、无服务、无数据库（索引除外）。

```
loom/
├─ core/            确定性内核（零 LLM）
│  ├─ repo/         书仓读写：front matter、容错读取、spec_version 迁移、
│  │                写入所有权矩阵 + 书仓写锁
│  ├─ legacy/       【GPL 隔离区】移植零件：合同引擎/CSV 检索/写前闸门/
│  │                时间线校验/记忆四态/run-ledger/RAG 降级链/评审纪律 prompt
│  ├─ prep/         上下文编译器：pack 槽位 + Book Map + 触发式注入 + L0/L1/L2
│  ├─ checks/       机检十项 + plan_gates 六道（全部零 LLM，读结构化 schema）
│  ├─ settle/       原子事务 + 哈希防串稿 + 批内工件失效锁
│  ├─ staging/      批次状态机 + 熔断器
│  ├─ ledger/       append-only 事件链 + signals 埋点 + 成本电表
│  ├─ migrate/      旧格式迁移器
│  └─ doctor/       体检 + 修复卡
├─ edge/            智能边缘（全部 LLM 调用）
│  ├─ client/       LLMProvider 实现：结构化输出、重试、模型路由、记账
│  ├─ renderer/     渲染（分档 + 关键章陪审团 best-of-N）
│  ├─ reviewers/    事实审 + 编辑审（输入构成见 §4.2；令牌绑定）
│  └─ scribe/       章摘要 + 事实提取 + 金句收割分类
├─ evolve/          品味闭环（离线，只读 signals）
│  ├─ analyzer/     signals 聚合分析 + 周报
│  ├─ bench/        网文-bench + 盲测集执行器
│  └─ optimizer/    提案->回归->holdout->人审->快照
└─ cli.py           唯一入口：init/plan/next/prep/render/check/review/
                    settle/batch/evolve/doctor/migrate
```

### 5.2 接口契约（两个 Protocol + 一个版本字段）

- `LLMProvider`（模型侧）：`complete_structured(schema, tier, ...)` 协议；路由表（渲染档/评审档/scribe 档/小档）实现该协议，换模型 = 换配置。所有边缘调用只有六类单发结构化请求，无 agentic 循环。
- `RepoPort`（环境侧）：git 与文件操作的抽象，core 全部环境访问走此口--测试替身可注入，settle 故障注入测试由此实现。
- `seam_version`：工作区文件协议缝上的 schema 版本声明；core 容错读取 + 版本嗅探，不匹配时显式降级而非静默错读。
- 记忆四态贯穿：设定与条目条目有 `active / outdated / contradicted / tentative` 四态，矛盾不入库（先 tentative + 人审），`loom memory correct` 留纠错痕。

### 5.3 模型路由与成本模型（估算，上线后以实测校准）

单章（3000 字正文，中文 ≈1 字 1.5 token）调用分解：

| 调用 | 输入 | 输出 | 模型档 |
|---|---|---|---|
| 决策卡（仅 L0/L1 档；L2 为零 LLM 模板投影） | 2.5k | 0.8k | 中档 |
| 渲染 | 5.0k（pack 全量） | 4.5k | 渲染档 |
| 机检十项（写侧）+ plan_gates 六道（规划侧） | 0 | 0 | 纯脚本 |
| 评审 ×2 | 2×5.5k | 2×0.6k | 中档 |
| 摘要+事实提取 | 5.5k | 1.2k | 小/中档 |
| 金句分类 | 1.0k | 0.2k | 小档 |
| 规划（摊到章） | - | - | 中档 |
| **合计** | **≈25k** | **≈8k** | |

- pack 预算恒定 → 成本随章数**线性**（相对全书长度亚线性）；prompt 缓存命中（合同/风格段批次内复用）再降 30–50%。
- 300 章总账 ≈ 7.5M input + 2.4M output tokens；三档路由参考（2026 年价格量级）：经济型 ≈¥0.15–0.25/章（300 章 ¥45–75）、均衡型（强模型关键章 7:3）≈¥0.3–0.4/章、品质型 ≈¥0.7–0.9/章。对照旧宿主 agentic 路线（单章 ¥2–5）节省 5–10 倍。
- **便宜模型中文文笔是最大未验证假设**--P1b 内用盲测金标准集出实测数据；不达标则降级为"便宜初稿 + 强模型润色"两段式，成本仍省一半以上。

### 5.4 关键实现要点

- **机检全部脚本化**：能数就进 checks，不能数才考虑进评审镜头。重复率用 n-gram；专名一致性对照名册触发器表；时间线用结构化锚点做单调性/区间校验（不走 LLM 估）；文体指纹七维直接统计。
- **settle 原子性**：写前校验 → 暂存树 → 单次 git commit（机器协议 message）→ index.db 自刷 → 清工作区；任一步失败整体回滚、工作区原样保留；哈希防串稿比对被审草稿与送审草稿 sha256。
- **结构化输出用紧凑 JSON**（缩进冗余实测 15–30%，生产路径不美化）；渲染正文除外（自然语言直出）。
- **few-shot 替代长上下文**：同场景金句 1–3 条 + 场景技能要点进 pack 固定槽位，实测可替代大段风格描述（省 40–60%）。
- **SQLite 工程纪律**：开 WAL + busy_timeout（多进程并发防 `database is locked`）；批量操作用事务而非逐条 upsert 全文件重写。
- **原子写重试**：Windows 瞬时锁文件错误（WinError 5）自动重试；初始化自动设 `git core.longpaths=true`。
- **防占位符**：合同引擎拒绝 "{章纲目标}" 类占位 query。
- **写入所有权与并发纪律（M6/N5）**：继承 v6 run-ledger 的写入所有权矩阵--每类文件/目录 × 每个环节（prep/render/check/review/settle/scribe/作者手改）的写权限白名单表，run-ledger 记录每次写入者；批次运行期间书仓持锁文件（含 pid），作者命令并发访问只读或显式拒绝；signals append 由内核独占。单书仓单写者，防双终端操作写坏状态。
- **测试与 CI 策略（N4）**：① core 表驱动单元测试全覆盖（零 LLM 天然确定性可测，机检十项/plan_gates 六道/结算事务逐项有用例）；② **prep 编译器确定性快照测试**--同书同章重编译 pack 字节一致（必要时按槽位容差比较），这是"上下文是编译出来的"原则的可测试形态；③ settle 故障注入矩阵（写树前/commit 前/刷缓存前各 kill 点 × 重放恢复）；④ edge 用 API 录制回放（cassette）测试，无 Key 可跑 CI；⑤ CI = Windows 单平台（唯一目标平台）+ 配置-实现一致性检查。
- **Windows 工程基线**（进 P0 验收）：全链路 UTF-8（文件读写、commit message 用 `-F` 文件方式、控制台输出显式 encoding）；长路径故障注入含">260 字符章文件 settle 成功"。
- **审计与遥测**：run-ledger append-only 事件链贯穿"计划→渲染→机检→评审→结算"全链路，任何一章可完整回放其生产过程（供 RCA 档案与进化分析）。

### 5.5 设计与资产来源（引用说明）

- **设计决策**：书仓九大不变量（文件即真相/派生物可丢弃/定稿只增不改/settle 原子性/写评分离/脚本<模型<作者/不在 VCS 里再造 VCS/容错读取/对话即编辑器）参考自同领域开源项目 v7 规格的已验证设计，本文按自身格式（loom-1）独立实现，不追求与其逐字节兼容。
- **可移植代码**：合同引擎、CSV 知识表检索、写前闸门、时间线校验、记忆四态、run-ledger（含写入所有权矩阵）、RAG 降级链、评审纪律 prompt 移植自作者本人早前工具 v6 的 Python 零件库--该库为 GPL-3.0，移植即传染，故本工具整体按 **GPL-3.0** 发布；移植代码集中 `core/legacy/` 隔离，未来若需更换许可仅需重写该目录。
