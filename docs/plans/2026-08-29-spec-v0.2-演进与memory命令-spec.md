# loom-1 spec v0.2 演进 + memory 命令 — 设计 spec

- 日期：2026-08-29
- 状态：设计已经 Human 批准（范围：演进与 memory 一起做；承载：去版本号重命名 + 版本记录节）
- 基线：`docs/plans/loom-1-格式规范-v0.1.md`（P0 冻结）；第二轮审阅报告 P2-3 与结论

## 背景与目标

第二轮审阅遗留两个规范外消费点（gate5 豁免绑定 `waiver.target`、plan_gates 卷章范围 `start_ch/end_ch`，均经 `model_extra` 游离在 schema 校验外），审阅结论指明下一阶段为 "spec v0.2 / 记忆四态"。本设计把两字段转正为声明字段、将记忆四态迁移规则成文，并落地 `loom memory` 纠错命令，使"纠错走人审 + settle 事务"成为可执行路径。

## 非目标

- 不改 `spec_version: loom-1` 字符串与 `SEAM_VERSION`（增量兼容演进，旧书仓零迁移）。
- 不做条目账本（大纲/条目/**）的人工状态迁移（账本状态由章管道/retcon 驱动，不归 memory 命令管）。
- 不实现 signals 新事件类型（熔断与 P4 分析不消费记忆迁移；审计走 run-ledger）。
- 不动 spec 开放议题四项（pack 规范化/scribe 事件枚举/retcon 影响面/peace 阈值）。

## 决策记录（含被否方案）

1. **文档承载**：`git mv` 为 `loom-1-格式规范.md`（去版本号）+ 文内新增「版本记录」节，同步 README / AGENTS.md / loom-1-spec 技能卡 3 处指针。被否：原文件名不动（名实不一致）；新建 v0.2 全文副本（双头维护，违反仓库"无双头维护"惯例）。
2. **字段转正方式**：声明字段 + 默认 `None`，向后兼容（旧书仓 front matter 里的同名键解析时自然落入声明字段，checks 的 extra 读取路径删除）。类型非法由 pydantic 在解析期拒绝（fail-closed 前移），checks 层的运行时类型守卫退役。
3. **迁移规则**（v0.2 成文，作者专属）：

   | from | 允许 to | 说明 |
   |---|---|---|
   | tentative | active / outdated | 人审确认或放弃 |
   | active | outdated / contradicted | 过时降级或矛盾证实 |
   | outdated | active | 作者复活 |
   | contradicted | tentative | 人审后重起（矛盾不入库红线） |

   无删除终态：不物理移除条目（只增不改精神）。`paid` 为账本专属态，不在迁移矩阵。
4. **memory 命令形态**：零 LLM 纯内核（`loom/core/memory.py`）；`list` 只读盘点，`set` 走 settle 事务（`actor="author"`、标题 `fix(手改)`、`条目: -`），随事务落 run-ledger `memory_transition` 事件。被否：状态迁移进 signals（词汇表膨胀且无消费者）；author 绕过 settle 直写（违反"所有产物写入过所有权矩阵"红线）。

## 接口与数据结构

- `Waiver.target: str | list[str] | None = None`（§A1 豁免载体转正字段）。
- `VolOutlineFM.start_ch/end_ch: int | None = None`（§4.1 卷纲转正字段）。
- `loom/core/memory.py`：`TRANSITIONS` 矩阵、`MEMORY_DIRS = ("定稿/设定", "定稿/记忆")`、`MemoryTransitionError`、`list_entries(repo, status=None)`（跳过无 status 的文件）、`set_status(repo, label, new_status, reason)`（label 匹配 front matter `id` 或仓内相对路径；reason 必填入审计链）。
- CLI：`loom memory <书仓> list [--status S]`；`loom memory <书仓> set <entry> <new_status> --reason "..."`。非法迁移/未知条目/缺 reason → 可读报错退出码 1，工作区原样保留。
